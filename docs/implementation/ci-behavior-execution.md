# CI 行为检查的执行方式

CI 使用 `swift test --no-parallel --jobs 2`。`--jobs 2` 约束构建并发；Swift Testing 默认并行执行独立测试。多个行为套件共享 MainActor，并包含加密文件处理和同步子进程验证，因此显式逐一执行测试以隔离套件之间的调度影响。[官方说明](https://developer.apple.com/documentation/testing/parallelization)也明确：套件上的 `.serialized` 不约束其他独立套件。

同候选 `aaa575984b5a29fd28baf60819601f498cb02272` 的 [PR CI](https://github.com/patrick-fu/queued-dictation/actions/runs/37069409337) 实际失败：192 个测试、18 条公共等待超时，涉及快捷键录音、App 入口、录音和收藏。公共等待截止为 2 秒，模型管线等待为 5 秒。

2026-10-03 在隔离源码副本中，只增加测试观测，用同一编译产物、原等待截止和完整测试集合进行一次单变量对照；两次命令分别采用 `--parallel` 与 `--no-parallel`，均退出 0。

| 实际指标 | 并行 | 串行 |
| --- | ---: | ---: |
| 完成的测试函数／套件 | 192／12 | 192／12 |
| 耗时 | 13.691 秒 | 16.454 秒 |
| 事件记录的最大套件重叠 | 12 | 1 |
| 最大测试函数／参数案例重叠 | 126／89 | 1／1 |
| 公共等待中一次 yield 的暂停 | 最大记录 509.660 毫秒 | 均未超过 100 毫秒记录阈值 |

串行运行仍通过真实 HTTP 的三主请求、三独立带教请求、FIFO 和卡片到达顺序检查。该参数控制测试之间的调度，测试函数内部继续运行产品的异步并发行为。

CI 使用 Testing Library 124.4，本机为 1501；本机并行控制没有复现原红。因此，18 条 CI 超时的具体根因仍未确认，不能将本次通过表述为已修复产品缺陷。新的执行方式需要由实际 CI 结果验收。
