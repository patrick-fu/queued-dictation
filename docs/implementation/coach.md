# 文本带教与方案 C 卡片流切片（#32）

本切片提供独立文本带教配置、通用 Chat 客户端、独立请求池、卡片状态和 AppKit 窗口；尚未接入 #26 的录音／转写事件、既有加密历史和主 App 菜单。它不代表 #32 整票完成，也不包含 #33 的音频带教能力。[父规格 #22](https://github.com/patrick-fu/queued-dictation/issues/22) 和最终决议覆盖旧布局原型中的流利度、评分及双开关假设。

## 可集成边界

- `CoachWorkScheduler` 是唯一请求池。每段有效的未经润色原转写调用 `enqueue(segmentID:rawText:language:cancelled:attemptID:)`，不等待润色。主队列和 App 不再另外持有带教并发池。
- 默认关闭，独立并发默认 3、范围 1–10，完整请求截止默认 30 秒、范围 5–600。降低并发只停止补充新请求，不取消已有有效请求。排队、缺配置和外部恢复门禁等待不消耗请求截止。
- `language` 省略时采用保守本地规则：字母至少有一个且全部是汉字才明确非英语并跳过；含 Latin 字母的英语／中英混说、其他脚本或不确定文本交同一次带教模型。显式 `.clearlyNonEnglish` 可用于调用者已有确证的语言信息。此规则仅做保守路由，不证明英语能力，也没有额外分类模型。
- 空文本、已取消片段和明确非英语没有请求。有效工作复用 `ModelRoleConfiguration` 和 `ServiceSettings` 中的服务；每次实际派发读取最新的服务、模型、`credentialID ?? service.id` 密钥引用及完整提示词。钥匙串不在排队或设置展示时读取。
- `onUpdate(CoachWorkUpdate) throws` 是持久化边界，结构可 Codable：`identity`（片段／尝试 ID）、`status`、实际 `dispatch`、`result` 和稳定 `failure`。`inFlight` 保存成功后才派发网络，`succeeded` 保存成功后才出卡；保存失败不出卡、不自动重发。`dispatch` 包含实际服务 ID、模型、完整提示词和截止，不含密钥。所有含口述或提示词的历史产物由集成层写入既有加密存储。
- `canDispatch(identity)` 是 #26／后续恢复规则的门禁；返回 false 时工作等待主动恢复，带教不会阻塞主交付。集成层须按当前片段／角色／尝试身份、自动发送时间窗和重启恢复决定，不能以默认 true 代替这些产品规则。
- App 的 `scheduler.onChange` 统一刷新菜单／胶囊状态并调用卡片控制器 `render()`；当前输入屏幕由已有本地焦点守护提供，不作为模型请求数据。
- `configurationChanged()` 仅续发尚未发送且仍有效的工作；失败／超时没有自动重试。显式重试使用新的 `attemptID` 再 enqueue。`stopProcessing()` 取消本地请求并停止回调，但不写成用户取消；重启后的在途／待发状态由恢复清单处置。
- 同步观察回调允许取消、删除、关闭或停止调度器；queued 先登记为尚不可派发，回调保存成功且工作仍有效才可派发。每次回调后重新确认当前身份和停止世代，从当前 pending 继续调度；保存结果时保留可失效身份直到回调返回，删除后不能补写失败或出卡。停止使当时调用栈里的 enqueue／pump 失效，之后显式提交的新工作可正常运行。

## 请求与结果契约

只 POST 所选 Base URL 的 `/chat/completions`，非流式 JSON 包含模型、system 完整提示词和 user 本段原转写。没有音频、其他片段、屏幕、窗口或剪贴板数据，没有独立分类／修复请求，也不发送未经核验的 `response_format` 能力参数。实际请求成功仅说明这一文本样本兼容；模型列表、schema 标签和本切片均不证明音频或严格 schema 能力。

完整默认提示词只有一份，可编辑，一键恢复当前默认。保存 nil 表示使用当前默认，custom 原文随配置保存和回读，升级不主动覆盖。提示词要求有文字依据、有价值才出卡，并禁止无音频的发音、停顿、节奏、流利度评价与数字评分。

合法返回是 `{"kind":"no_card"}`，或 `{"kind":"card","suggestions":[...]}`。一段最多一卡，suggestions 必须 1–2 条，每条只含 `category`（grammar／expression）、`original`、`improved`、`reason`。字符串非空、无非法控制符，每字段最多 8 KiB；原表达必须逐字出现在该段 raw，改进不能与原表达相同。其他字段（包括评分）、空卡、第三条建议、未知类别、围栏及无依据原表达均明确失败，不弹空卡，不请求模型修复。

客户端限制完整响应 1 MiB、原转写 256 KiB；完整截止覆盖上传、等待、响应头和响应体读取，并实际取消 URLSession 任务。禁止重定向和交互式额外鉴权；错误只映射稳定中文原因，不显示服务返回的正文／密钥。格式校验不能证明教学建议的语义质量或原意保持，真实 BYOK 样本仍须独立验证。

## 卡片与关闭语义

`CoachPanelState` 保留真实到达顺序，不等待早期片段、不按口述顺序重排；每张卡标记片段 ID。单卡“看完并移走”只删展示；历史保存回调不受这个操作影响。关闭总开关清空整窗、取消未发工作并尽力取消在途。关闭前已有有效响应即使迟到也只入历史，重新打开也不弹旧卡；超时、主动取消、删除和旧尝试迟到完全失效。`removeSegment` 在删除前调用，删除后不发任何可能重建历史的 update。新开关周期只接受此后的新工作。

`CoachPanelWindowController` 使用 AppKit nonactivating NSPanel，禁止成为 key／main window，不调用 App 激活；浮窗约 380×550，约两卡高度，更多卡片向上滚动，新卡到达后滚至底部。没有自动消失计时器。默认右下，四角相对 `NSScreen.visibleFrame`；调用者提供当前输入所在屏幕，缺活动输入时沿用上次屏幕，屏幕已移除时回到首个可用屏幕。Space／屏幕变化重定位，collectionBehavior 允许全屏辅助与所有 Space。整窗关闭调用与菜单同一 `setEnabled(false)`，不是仅隐藏。

`CoachSettingsWindowController` 只保存带教角色与独立参数，选择已有共享服务；不复制凭据写入逻辑。每个菜单项直接绑定服务 UUID，保留同名服务及与“尚未选择”同名的真实服务，placeholder 没有 UUID；合法小数截止完整回显、保存不截断。共享服务编辑入口由 App 注入，并复用 #28 的服务 CRUD。设置窗手动打开时可获取焦点；这不同于自动出现的卡片窗。

## 实际验证与限制

已执行 `swift test --filter CoachBehaviorTests`（13 项测试函数，包含 9 个响应分支和 2 个存储拒绝分支），以及完整 `swift test`（65 项、4 套件），均 exit 0。测试先在缺实现、中文尚未跳过和等待原因未更新时得到对应失败，再修正；网络使用真实 TCP loopback、fake key 和合成文本，未读取生产凭据或上传用户音频。

独立审查后追加同步重入回归：queued／inFlight 回调内删除、关闭、取消、停止（8 分支）均不发该段 HTTP／不复活结果，正常新段仍成功；onChange 中停止拒绝栈内旧 enqueue；门禁删除其他 pending、waiting 回调删除、保存结果回调删除并抛错，均不沿用旧快照或补写已删除历史。合法已发结果的保存回调关闭总开关只入历史，重开不重放卡。修复前真实 loopback 对照实际收到旧段和新段两次请求、旧段 succeeded 及卡片；修复后只收到正常新段一次请求。修复后的带教检查 19 项和完整检查 71 项／4 套件均 exit 0，原生构建 exit 0。已通过的最高层检查保持保守语言路由、最新配置、完整截止与加密接线边界。

隐藏 AppKit 对象对照（未激活 App、未呈现窗口）：修复前同名／placeholder 同名项从四项合并成两项，并使第二个服务和 placeholder 同名服务保存成 nil；5.75 秒回显为 5、保存成 5.0。修复后四项全部保留，三服务均按原 UUID 回读／保存，placeholder 可清空角色，5.75 秒原样保留；各窗 isVisible=false。此验证不扩大为实机交互或焦点验收。
